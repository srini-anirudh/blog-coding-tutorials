The plan

When a vision-language model starts to prefer the true answer after post-training, did it look at the image, or did it learn which words tend to win?

Most of this tutorial exists to answer that question with numbers. A VLM can lower a preference loss without using a single pixel. It can also raise a visual reward by gaming the reward. Both failures look like progress on a training curve.

So we build the alignment stack on images where we know every fact exactly. We draw the image ourselves, so we know the true colour, count, position and text. That makes every preference label and every reward exact, and it lets us run controls that real datasets cannot.

We post-train a real pretrained model, HuggingFaceTB/SmolVLM-256M-Instruct. The tiny VLM from C7 and C8 is not capable enough for this. Preference learning and RL refine a model that can already do the task sometimes. A model that cannot read a colour gives DPO and GRPO nothing to refine.

Clone the repo once. Every command below runs from its root, using the shared virtual environment.

Nuance

Every run here is short: 60 to 150 update steps on a shared laptop. The numbers are real, and they are small. Treat them as a working demonstration of the method, not as a benchmark of SmolVLM. Where a gain is within the noise of a held-out set of this size, the text says so.

Step 01

Draw scenes where the truth is exact

Goal A seeded image generator, and questions whose answers we compute instead of annotate.

A scene is a few coloured shapes and one printed word on a white canvas. Objects live in distinct cells of a 3 by 3 grid, so they never overlap. Each pair of colour and shape appears at most once, which keeps every question unambiguous.

[[L vlmalign/scenes.py | ^def sample_scene | auto | 2,16-20 | One seed gives one scene. Drawing at 512 pixels matches the size SmolVLM uses, so we avoid a resample.]]

Questions come with a sentence template that has one slot. This is what makes hallucination negatives cheap later: a rejected answer is the same sentence with one slot changed.

[[L vlmalign/tasks.py | ^def ask | 26 | 8,13 | Two of the five question kinds. The answer is computed from the scene, and the template holds one slot.]]

Next, load the model. SmolVLM normally splits a large image into tiles. Our scenes do not need that, so we switch it off. One 512 by 512 tile gives 64 image tokens instead of 1,088, which makes every later step faster.

[[L vlmalign/model.py | ^def load_processor | auto | 2-4 | Turning off tiling. The first run of this tutorial had 1,141 tokens per prompt. This line brings it to 81.]]

Step 02

Generate hallucination negatives

Goal Turn every question into a preference pair, in two versions: one that needs the image, and one that does not.

A multimodal preference example has four fields: image, prompt, chosen, rejected. The chosen answer states the true fact. The rejected answer is a hallucination we manufacture, and it comes in five kinds: wrong colour, wrong count, wrong object, false OCR and wrong spatial relation.

How we draw the wrong value matters more than anything else in this step. So we write two samplers that share everything else.

[[L vlmalign/preference.py | ^def wrong_value | auto | 5-6,8,10,12,14-15 | The balanced sampler draws from the same set as true values. The biased sampler uses tempting shortcuts.]]

Try both. Pick a kind, switch the sampler, and read the note under the pair.

A note on true values. If we let true counts follow the scene generator, they skew towards 1 and 2. Then a rejected answer of 3 would mostly appear on the rejected side, and text alone would predict the label. So build_pairs picks the target true value first, uniformly, then searches for a scene that has it.

[[L vlmalign/preference.py | ^def build_pairs | auto | 14-19 | Stratify on the true value first. Then true and wrong values have the same uniform distribution, which makes each pair exchangeable.]] [[O results/show_pairs.log | scripts/show_pairs.py | --- balanced | rejected The blue triangle is to the right]]

Test

A negative must be false for this image, and balanced values must appear about equally on both sides. test_negatives_are_always_false and test_balanced_pairs_are_exchangeable check both.

Checkpoint

  • You can read a pair and predict the answer only by looking at the image, on the balanced side.
  • On the biased side, you can often answer without the image. Keep that in mind for step 6.
Step 03

Turn one pair into tensors

Goal A batch where chosen and rejected share an image, and only answer tokens carry a label.

Each pair makes two rows. Both rows hold the same prompt ids, and then their own answer. We tokenize the answer separately and append it. That keeps the prompt ids identical to what generate() conditions on, so we train on the same probabilities the model samples from.

[[L vlmalign/model.py | ^def encode_answer | auto | 9-10 | The answer ends with end_of_utterance, because stopping is part of what the model must learn.]]

Now build the batch. Rows are padded on the right, labels are -100 outside the answer, and each row keeps an index into a smaller tensor of distinct images.

[[L vlmalign/logprobs.py | ^def build_batch | auto | 10-12 | Prompt and padding positions stay at IGNORE, which is -100.]] [[L vlmalign/dpo.py | ^def pair_batch | auto | 13-14 | Row 2i is the chosen answer, row 2i+1 the rejected one. Both point at image i.]]

Look at what actually comes out. Two pairs give four rows and two images.

[[O results/show_pairs.log | scripts/show_pairs.py | --- one batch | mask=0]]

Label the whole row instead of the answer: in build_batch, change labels[i, len(p): len(r)] to labels[i, : len(r)]. The sum now includes the 64 <image> positions and the prompt. The difference between chosen and rejected barely changes, because those positions match across rows, but the value of each sum becomes large. test_batch_shapes_and_label_mask fails on the first assert about IGNORE.

Step 04

Compute sequence log-probabilities, naively and then fast

Goal One number per row: the log-probability of its answer, verified against the Hugging Face loss, with the vision encoder run only once per image.

Everything in DPO and GRPO reduces to one quantity, the sum of log-probabilities over answer tokens. The tensor work is three lines: shift, log-softmax, gather.

[[L vlmalign/logprobs.py | ^def token_logprobs | auto | 6-9 | Position t predicts token t+1, so logits drop their last position and labels drop their first.]]

The naive way to get logits is to hand pixel_values to the model. It runs the vision encoder once per row. But chosen and rejected share an image, and G rollouts share an image. So we run it once per distinct image and write the features into the placeholder slots ourselves.

[[L vlmalign/logprobs.py | ^def merge_image_tokens | auto | 7-9 | masked_scatter fills the image slots with features in order. Gradients flow through it into the connector and the vision encoder.]] [[L vlmalign/logprobs.py | ^def forward_logits | auto | 9-14 | The naive path and the fast path. A test proves they return identical logits.]]

Test

Compare against a trusted implementation. Our sum must equal minus the Hugging Face mean cross-entropy times the number of answer tokens. The tests use a tiny random Idefics3 with SmolVLM’s module layout, so they run offline in seconds.

[[L tests/test_logprobs_dpo.py | ^def test_sequence_logprob_matches_hf_loss | auto | | Our log-probability against the Hugging Face loss. Passing means our shift and mask match the library's.]]

Now measure what the fast path saves. One forward and backward pass on one image and G rollouts, with all three model parts trainable.

Step 05

Write image-conditioned DPO by hand

Goal The DPO loss with the image inside every term, trained on balanced negatives, with no second model in memory.

The derivation is in the theory post. Here is what the loss looks like in code. The image does not appear in this function, because it is already inside each log-probability.

Derivation inTeaching a model what we prefer [[L vlmalign/dpo.py | ^def dpo_loss | auto | 4-6 | The implicit rewards are log-ratios against the reference. The margin is their difference.]]

The standard loss needs a reference model. A full second copy of SmolVLM costs about 1 GB. We avoid it in two ways. First, the reference never changes, so we score every training pair once and keep the numbers. Second, we train a LoRA adapter, whose zero initial state means a fresh adapter leaves the model exactly at the reference.

[[L vlmalign/dpo.py | ^def reference_logprobs | auto | | Score the frozen starting model once, then keep two numbers per pair.]]

TRL makes the same two choices. Its DPOTrainer has precompute_ref_logps, it can use a disabled adapter as the reference, and its default loss line is -F.logsigmoid(self.beta * delta_score), which is the same as ours. We write ours by hand so nothing is hidden, not because the library is wrong.

[[L vlmalign/lora.py | ^class LoRALinear | auto | 7-8,13 | B starts at zero, so a fresh adapter is an exact no-op. A test checks this, and another compares against PEFT.]]

Here is one training step, from the script.

[[L scripts/train_dpo.py | ^ for step in range\(args.steps\): | 8 | 2-6 | One DPO step. Pair indices select both the batch and its stored reference values.]] [[O results/dpo_balanced.log | scripts/train_dpo.py, Apple M5, MPS | \[dpo_balanced\] reference | step 149 | ^(\[dpo~step)]] [[RESULT_DPO]]

Break it

Remove the reference: set ref_chosen and ref_rejected to zero. At step 0 the margin is no longer zero, because long answers have large negative log-probabilities that do not cancel when chosen and rejected tokenize to different lengths. test_dpo_loss_is_log2_when_policy_equals_reference is the check that catches this: the loss at step 0 must be exactly ln 2.

Checkpoint

  • The first batch has loss 0.693 and margin 0.
  • test_one_dpo_step_increases_the_margin and test_fresh_lora_is_an_exact_no_op pass.
Step 06

Check whether the preference needs the image

Goal Two judges that cannot see: a text-only probe on the dataset, and the VLM on grey images.

Nothing in the DPO loss forces the model to use the image. If the words predict the label, the cheapest way to lower the loss is to learn the words. Agrawal and colleagues showed the same effect for VQA, where models learned answer priors from biased splits. So we test for it directly, in two ways.

Judge 1: a text-only probe on the dataset

This judge never loads the model. It is a logistic regression over word counts, predicting which of two answers was chosen. Its features flip sign when the two answers swap, so it cannot learn to prefer whichever comes first.

[[L vlmalign/blind.py | ^def pair_features | auto | 7-8 | Antisymmetric features, plus prompt-by-answer crosses. The probe has no bias term.]] [[O results/blind_probe.log | scripts/blind_probe.py | negatives ]]

On balanced pairs the probe scores about chance on held-out data. On biased pairs it reaches 100% for colour, count and object, and 99% for OCR. Spatial stays near chance in both, because a flip of left and right has no text-only hint. The biased total sits near 91% only because spatial pulls it down.

Insight

Exchangeability gives this check a clean zero. If (a, b) and (b, a) are equally likely as (chosen, rejected), then any scorer that ignores the image is right on one and wrong on the other. So it scores 50% in expectation, whatever its priors are. Any held-out score above 50% on such a set must come from the image. You do not get this guarantee on natural data, which is why the stratification in step 2 is worth its few lines.

Judge 2: the VLM on a grey image

The second judge is the model itself. We replace every image with a grey square of the same size and score the same pairs. The code path is the same: we only swap the images passed to pair_batch.

[[L vlmalign/evaluate.py | ^def preference_accuracy | auto | 10 | The blind path differs by one line: the image.]] [[RESULT_BLIND]]

Break it

The biased run is itself the failure. Train it next to the balanced run and compare them on balanced pairs, as the figure does in its last stage.

Checkpoint

  • test_text_probe_sees_bias_but_not_balance passes.
  • You would now run this probe before any preference training, because it costs seconds and needs no GPU.

Step 08

Build visual GRPO

Goal G sampled answers per image, rewards from the scene, relative advantages, one policy update.

GRPO needs no value model. For each image and prompt it samples G answers and compares them with each other. The method comes from DeepSeekMath, and the theory post covers why it works. We only add the image.

Derivation inHow reinforcement learning teaches models to reason [[L vlmalign/grpo.py | ^def group_advantages | auto | 7,9 | Each answer is compared only with others for the same image. We keep the optional std scale, and Dr. GRPO's variant without it.]]

Rollouts are sampled at temperature 1 with no top-k or top-p, so that we sample the policy we then differentiate. Every row in a group shares one image, so the fast path from step 4 pays off here most.

[[L vlmalign/grpo.py | ^def sample_group | auto | 5-8,13 | num_return_sequences gives G samples for one image. Everything after the first end_of_utterance becomes padding.]] [[L vlmalign/grpo.py | ^def grpo_loss | auto | 8,10 | The clipped objective. With one update per batch the ratio is 1, so the gradient is the advantage times the score. KL to a reference is optional.]] [[O results/show_rollouts.log | scripts/show_rollouts.py | prompt: | answer tokens per row ]]

Read the third group. All eight samples are wrong and identical, so every advantage is zero. Nothing is learned from that image, however bad the answers are.

One training step, from the script. It is short because the pieces already exist.

[[L scripts/train_grpo.py | ^ # 1\) rollouts | 16 | 2-5,11,13 | One visual GRPO step. We also log a strict reward, even when training on a weak one.]]

Nuance

We set the KL weight to zero by default, as Liu and colleagues recommend in Dr. GRPO, and take one update per batch. The code supports both a KL term and several updates, with clipping, but a short laptop run does not need them. Setting them differently is a real choice to evaluate, not a free default.

Checkpoint

  • test_group_advantages_are_relative_within_each_image and test_on_policy_grpo_gradient_is_advantage_times_score pass.
  • A flat group gives zero advantage in your own printout.
Step 09

Ask whether RL improved perception or reasoning

Goal The same GRPO run three times, with different parts allowed to learn, and tests that separate seeing from counting.

Counting is SmolVLM’s weakest skill here, so it is the task with the most room to move. We run GRPO on it with exact-match reward, three times. The seed and the data are the same. Only the trainable set changes.

[[L vlmalign/freeze.py | ^def configure_trainable | auto | 7-13 | Freeze everything, then open up one part at a time. A test checks that image features cannot change when the vision encoder and connector are frozen.]]

An accuracy gain alone does not separate perception from reasoning. So we measure three things after each run.

  • Counting from pixels. The training task itself, on 100 held-out images.
  • Counting from text. We write the objects in the prompt and show a grey image. Here perception is not needed.
  • The perception probe. A fresh linear probe from pooled image features to per-shape counts, on 800 other scenes. If it improves, the features changed in a useful way.
[[L vlmalign/evaluate.py | ^def text_count_accuracy | auto | 4-6 | The control for reasoning: the same counting question with the objects written in the prompt and a grey image.]] [[L scripts/perception_probe.py | ^def probe_accuracy | auto | 4 | The control for perception: ridge regression from image features to per-shape counts.]] [[RESULT_FREEZE]]

Checkpoint

  • test_freeze_modes_control_what_moves passes for all three modes.
  • results/grpo_count_exact_*.json and results/perception_probe.json hold your own numbers.
Step 10

Hack the reward on purpose

Goal Train on a weak reward, watch how the policy responds, and build the monitors that catch it.

The prompt is List the colors of the shapes in the image. The weak reward is recall: the fraction of true colours mentioned. A caption that names every colour earns full marks. Hallucinated colours cost nothing, which links this step back to the start of the tutorial.

[[L vlmalign/rewards.py | ^def caption_recall | auto | | The weak reward. Nothing penalises naming a colour that is not there.]] [[L vlmalign/rewards.py | ^def caption_f1 | auto | 3-6 | The fix. A hallucinated mention costs precision.]]

The monitors are small. We count the colours named, the colours named that are not in the image, the answer length, and a strict reward we do not train on. We log them on every step, whatever the training reward is.

[[L vlmalign/rl_tasks.py | ^def caption_stats | auto | | Monitors. The training reward cannot see them, so they cannot be gamed by accident.]] [[RESULT_HACK]]

Checkpoint

  • Your log shows colors= and halluc= next to the reward.
  • You can name, for each reward in this post, one output that games it.

Exercises

  1. Grounding with GRPOHard Add a task that asks for the box of a named object, using box_reward. Train it on the weak center_in_box reward and then on IoU. Log mean box area as the monitor.
    Hint

    SmolVLM rarely writes four numbers unprompted. Give the format in the prompt, and count how many rollouts parse at all. If none parse, every group is flat, and nothing is learned.

  2. Measure the shortcut per kindMedium Make only OCR biased in wrong_value and leave the rest balanced. Train DPO and report grey-image accuracy per kind. Does the shortcut stay in OCR, or does it reach the other kinds?
  3. Add a shape of the wrong kind of hardMedium Make object sizes smaller in sample_scene and rerun the perception probe on the pretrained features. Find the size at which counting stops being linearly readable.
    Hint

    A 16-pixel patch merges into one token per 64 pixels. Objects smaller than that share a token.

  4. Switch off the std scaleEasy Pass scale_by_std=False to group_advantages and compare counting after 60 steps. Then compare the fraction of groups with one correct answer at each setting, to see how Dr. GRPO changes the weight of those groups.
  5. A better shortcut meterHard Replace the bag-of-words probe with a small sequence model trained on the same pairs. Can a stronger blind judge beat 50% on the balanced set? If it does, you have found a leak in the generator, and you should fix it.
