Step 11

Derive the parameter count, then verify it

Goal Write the size of every component as a formula, and check it against real modules and published model sizes.

If you can write the parameter count by hand, you understand the architecture. Every term comes from a matrix we already built.

The check builds each model on PyTorch’s meta device, which records shapes and allocates no memory. So Llama 3 8B fits on a laptop for counting.

Formula and module agree on all three. The totals also agree with outside sources. SmolLM2-135M has 134,515,008 parameters when loaded from the Hub in step 12. Llama 3 8B’s published size is 8.03B, and our formula gives 8,030,261,248. Try the formula yourself. A preset button fills in a real model, and a bad combination raises the same error as ModelConfig.

Insight

Our script shows Llama 3 8B's attention at 2.147B parameters with 32 KV heads, 1.342B with 8, and 1.107B with 1. Going from 32 KV heads to 8 removes 10% of the whole model, but it removes 75% of the KV cache: 2.00 GiB becomes 0.50 GiB for 4096 tokens. So GQA is mainly an inference-memory decision, and only secondarily a parameter saving.

Checkpoint

  • All three totals print equal=True.
  • test_parameter_count_formula_matches_model and test_parameter_count_of_real_models pass.
Step 12

Prove it against the trusted implementation

Goal Give our weights to Hugging Face’s LlamaForCausalLM and get the same logits. Then load real pretrained weights into our model.

So far each module passed its own small test. That cannot catch a wrong design choice that we made consistently, such as the RoPE pairing. A second, independent implementation can. Because we named our attributes after Hugging Face’s, the conversion is a config translation and a key prefix.

The logit difference is exactly zero, in both directions. A real pretrained model runs through code we wrote today, and greedy decoding matches generate() token for token. The model itself is a small one, which shows in its answer.

Nuance

Exactly zero means both paths ran the same floating-point operations in the same order, here through the same SDPA kernel. Do not expect that as a general rule. Our naive backend computes the same function and differs by about 1e-6, because its operations run in a different order. So the test uses a tolerance of 1e-5, and a bitwise match is a pleasant result and not a requirement.

Checkpoint

  • Random tiny model and SmolLM2-135M both match within tolerance.
  • test_logits_and_loss_match_llama passes. test_smollm2_135m_logits_match passes with -m network.

Step 14

Cached generation: same tokens, far less work

Goal Keep past keys and values, prove the output does not change, and measure the saving.

Theory inThe mechanics of LLM inference

Start naive. To get one new token, run the whole sequence again and keep the last row of logits. This is correct and very wasteful, because past tokens do not change. Their keys and values do not change either. So we store them and pass only the new token.

Key insights and nuances

  • A wrong design choice can still write fluent text. Swapping the RoPE channel pairing left SmolLM2 fluent and raised its loss by over a nat per token. Only a numerical comparison catches this. Step 4
  • A bitwise match is a bonus, and a tolerance is the requirement. Our SDPA path differs from Llama by exactly 0, and our naive path by about 1e-6, though both are correct. Step 12
  • RMSNorm has a floor. Below an input RMS near sqrt(eps) it stops rescaling. Real embeddings at RMS 0.02 already lose about 1.2%. Step 3
  • SwiGLU is where the parameters are. It holds 59% to 75% of the three models we counted. Step 6
  • GQA is an inference-memory decision. Going from 32 KV heads to 8 in Llama 3 8B removes 75% of the cache and 10% of the parameters. Step 11
  • Depth scaling keeps a new model near identity. Without it, a 48-layer stream ends about 12 times larger before any training. Step 10
  • A chunked-prefill mask bug hides for a long time. is_causal=True is safe for one token at a time and for a full forward. It only breaks when queries are several tokens shorter than keys. Step 5
