The plan

What is inside a modern language model, tensor by tensor? And how do you prove that your version is correct, and not only plausible?

We answer both by building one. The model follows the Llama design, which is also the design of SmolLM2, Qwen and many others. It differs from the 2017 transformer in four places. It uses RMSNorm instead of LayerNorm. It uses RoPE instead of added position vectors. It shares keys and values across query heads. It replaces the plain MLP with a gated one.

Why these changesWhat changed inside the transformer

This post does not repeat those arguments. It writes the code, runs it, and looks at the tensors. Each step adds one module and one check. At step 12 we hand our weights to Hugging Face and ask for the same logits. Then we run the other direction and load a real pretrained model into our own code.

The attention code comes from Build Attention From Scratch. We keep its GQA and RoPE design and its names, trimmed to what a decoder needs, and a test checks that the two agree. Every number below came from these scripts on an Apple M5. Commands run from the repo root.

Step 01

Put every number in one configuration

Goal A dataclass that describes the whole architecture and rejects impossible shapes early.

Every module reads its sizes from one object. That lets us save the architecture next to the weights, translate it to Hugging Face later, and build Llama 3 8B on the meta device from one line.

Three of the checks encode real constraints. Head width must be an integer. Query heads must divide evenly among key and value heads. RoPE rotates pairs of channels, so head width must be even.

Step 02

Token embeddings and weight tying

Goal Turn ids into vectors, and use one matrix for both reading and scoring tokens.

An embedding is a lookup table: X = E[ids]. The table has V rows and D columns. The same id always returns the same row, at any position. Position enters later, inside attention.

We use a byte tokenizer, so V is exactly 256 and nothing needs downloading or training. The next tutorial replaces it with a trained BPE tokenizer.

Weight tying means the output layer reuses the embedding matrix. Tying is one assignment in the constructor. After it, both names point to the same Parameter, and gradients from both uses add up in one place.

Shapes in step 2
TensorShapeMeaning
input_ids(B, T)Integers in 0 to V - 1.
embed_tokens.weight(V, D)One learned row per token.
x(B, T, D)The row for each token.

Nuance

Tying saves little in this model: 65,536 of 4.36M parameters, or 1.5%. In SmolLM2-135M it saves 28.3M of 162.8M, or 17%. The saving grows with vocabulary size, while the body of the model does not depend on V. That is why large models with big budgets, such as Llama 3 8B, can afford to leave it off.

Checkpoint

  • Both uses of a byte give the same vector.
  • test_weight_tying_shares_storage passes.
Step 03

RMSNorm from scratch

Goal Rescale each token vector to unit root-mean-square, with no mean subtraction and no bias.

Derivation inThe geometry of normalization

RMSNorm is LayerNorm without the centring. It divides each token by its own RMS, then applies a learned gain per channel. It has D parameters and needs no running statistics.

The first lines hold a surprise. An input with RMS 0.0194 comes out at 0.9869, and one with RMS 0.001 comes out at 0.2921. The reason is epsilon. The output RMS is r / sqrt(r² + eps), so with eps = 1e-5 the norm stops rescaling once r falls near sqrt(eps), which is 0.0032. Drag the slider to see it.

Insight

Our freshly initialised embeddings have RMS 0.020, so the first norm in the model loses about 1.2% to epsilon. That is harmless at this scale. It would not be harmless at initializer_range = 0.002. Here the first norm would return vectors far below unit scale, and every layer after it would see a weak signal. Check what eps does before you shrink an init.

Test

test_rmsnorm_matches_torch compares against torch.nn.RMSNorm, which PyTorch added in 2.4. The maximum difference above is exactly 0.

Checkpoint

  • Output RMS is 1 for any input much larger than sqrt(eps).
  • test_rmsnorm_output_has_unit_rms passes.
Step 04

Rotary position embeddings

Goal Make the query-key score depend on the distance between two tokens, and not on where they sit.

Derivation inHow models know where they are

RoPE adds nothing to the token vector. It rotates each pair of channels by an angle proportional to position. Each pair rotates at its own speed. Queries and keys are rotated. Values are not. This is the same module as in Build Attention From Scratch.

Read the last four lines. The first three have offset 3 and identical scores, even at positions 100 apart. The fourth has offset 2 and a different score. That is the whole property, measured.

Shapes in step 4
TensorShapeMeaning
inv_freq(d/2,)One rotation speed per channel pair.
cos_cached, sin_cached(max_seq_len, d)Tables indexed by absolute position.
cos, sin(B, T, d)The rows for these T positions.

Break it

Some codebases pair channels as (0, 1), (2, 3) instead of (i, i + d/2). Both are valid RoPE, so a model trained with one is broken under the other. We load SmolLM2-135M and swap only the pairing. The result is the most dangerous kind of bug, because the model still writes fluent English.

Only the loss reveals it, up by more than a nat per token. A visual check of samples would pass. This is why step 12 compares numbers.

Checkpoint

  • Rotation keeps the vector norm.
  • test_rope_dot_product_depends_only_on_offset passes.
Step 05

Grouped-query attention, naive first

Goal A readable reference, a fast SDPA version, and a test that they agree, with a cache slot ready for step 14.

Derivation inHow attention moves information

Grouped-query attention keeps all H query heads and reduces keys and values to H_kv heads. Several query heads read each key and value head. The reshape helpers below are trimmed copies from the attention tutorial.

Next we hand the same maths to PyTorch’s fused kernel. There is one trap, and the code comments mark it. is_causal=True builds a triangle aligned to the top-left corner. That is correct only when queries and keys have the same length.

The module itself is mostly projections. RoPE tables come in from the model, so they are computed once per call and shared across layers.

How much does the fused kernel save inside the full model? We time forward plus backward, per training step.

Nuance

%%NUANCE_SDPA%%

Break it

Always pass is_causal=True, and prefill the prompt in chunks of 8 on top of a cache.

The first chunk is correct because it starts at the top-left. Every later chunk is wrong by up to 0.9 logits on random weights. Token-by-token decoding hides this bug, because a single query needs no mask. So the bug only appears when someone adds chunked prefill later.

Checkpoint

  • Naive and SDPA differ by about 1e-7.
  • test_naive_and_sdpa_agree and test_same_output_as_attnzoo pass. The second one checks tinyllm against the C3 library, including its cache protocol.
Step 06

SwiGLU, the gated feed-forward

Goal Implement down(silu(x W_gate) * (x W_up)) and understand why F is not 4D.

Background inWhy neural networks need nonlinearity

Attention mixes across positions. The MLP works inside each position. SwiGLU makes two wide copies of the token. One copy, after silu, becomes a gate that scales the other copy channel by channel. A third matrix projects back down.

A classic MLP with F = 4D has 8D² weights. SwiGLU with width F has 3DF. They match at F = 8D/3. That is the origin of the odd-looking numbers in real configs. SmolLM2-135M uses exactly 8D/3: 1536 for D = 576. Llama 3 8B uses more, 14,336 for D = 4096, which is a ratio of 3.5.

Insight

The word “feed-forward” undersells this layer. In all three models we count in step 11, SwiGLU holds the largest share of the parameters: 75% of tiny, 59% of SmolLM2-135M and 70% of Llama 3 8B. So if you need to shrink a model, F is the first number to look at, before heads or layers.

Checkpoint

  • Output shape equals input shape. Gate values never fall below -0.278.
  • test_swiglu_shapes_and_formula passes.
Step 07

The decoder block

Goal Assemble two pre-norm residual branches into a block whose output shape equals its input shape.

Each branch normalises its own input, computes, and adds the result to the stream. The stream itself is never normalised inside a block. That gives gradients a clean path from the loss to the first layer.

A fresh block is close to the identity function. With a unit-scale input, the attention branch has RMS 0.016 and the MLP branch has RMS 0.008. Training gradually grows these branches.

Checkpoint

  • block(x) matches the hand-computed sum exactly.
  • test_gradients_reach_every_parameter passes.
Step 08

The decoder stack and LM head

Goal Repeat L blocks, add a final norm, and score every token in the vocabulary at every position.

The stack is a loop. Two details matter. Positions must start after the cached tokens, which is the job of past. And the final norm is needed because the stream has never been normalised.

The last output line is a causality check on the whole model. Changing tokens at position 8 and later leaves logits 0 to 7 bitwise unchanged.

Step 09

The shifted cross-entropy loss

Goal Score each position against the token after it, and let callers mask positions out.

The model predicts the next token, so targets are the inputs moved left by one. The last position has no target. The first token is never predicted.

Break it

Remove the shift, then train for 100 steps. The loss looks wonderful, and the model has learned nothing useful.

Each position can read its own target, because attention includes the current token. So the model learns to copy, and sampling repeats the last character. A loss below the entropy of English text after 50 steps is a bug, not progress.

Checkpoint

  • The hand computation and causal_lm_loss agree to four decimals.
  • test_loss_is_shifted and test_loss_ignores_masked_labels pass.
Step 10

Initialisation

Goal Start near the uniform loss, and keep the residual stream stable at any depth.

Derivation inWhy transformers do not explode

Two rules cover it. Every weight starts small, with standard deviation 0.02. The two projections that write onto the residual stream are scaled down further by the square root of 2L, because each block adds two random contributions and their variance accumulates.

A correct model should start near ln V, the loss of a uniform guess. That number is your first sanity check on any new model, and it costs one forward pass. Here we also test what happens without the depth scaling, in a 48-layer model.

Insight

Without the depth scaling, a 48-layer model's stream reaches RMS 0.69 at the last layer. With it, the stream reaches 0.059, even though both start from embeddings of RMS 0.02. So the scaled model begins close to a stack of identity blocks. The unscaled one has already drifted by a factor of 12 before seeing any data.

Checkpoint

  • Initial loss on the tiny model is near ln 256 = 5.545.
  • test_initial_loss_is_near_uniform passes.
